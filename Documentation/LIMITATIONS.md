# Known limitations

- The available DMG has an ad hoc signature for local testing. Developer ID signing and notarization are pending. Login-item approval and Gatekeeper behavior need verification on the intended distribution build.
- The host has Command Line Tools, not full Xcode. Both architectures were compiled with swiftc against the installed SDK and minimum target macOS 14. The checked-in Xcode project passes plist validation but has not been built using xcodebuild on this host.
- Runtime testing used one Apple Silicon MacBook display on macOS 27.2. Intel was cross-compiled, not run. Sonoma/Sequoia and other supported versions, external physical monitors, display rearrangements, actual lid sleep/wake, lock/unlock, login after restart, thermal pressure, memory pressure and unplugged low-battery transitions need broader hardware/OS qualification. Automated sleep/session behavior tests post the same notifications to the local test process; they do not physically sleep or lock the user's Mac.
- macOS offers no general public system-managed arbitrary video wallpaper API. Moving uses desktop-level windows while running. No animation is installed at the login/lock screen; Finder, Spaces, Mission Control, widgets, Stage Manager, desktop reveal animations and future WindowManager revisions can impose limitations outside the app's control. Normal desktop Spaces use the same assignment per display. Public APIs do not support reliable independent per-Space assignments.
- Screen-lock distributed notifications are advisory and not a documented Apple contract. Public display-sleep and inactive-session events provide fallback suspension, but lock-only power behavior and launching while already locked cannot be guaranteed on every macOS release. No private lock-state query is used.
- Independent displays use independent players and may not be frame synchronized. Additional active displays increase decoding load. Mirrored displays follow macOS's screen mirroring topology.
- Loop continuity depends on how the source is edited. AVPlayerLooper avoids manual rewind gaps but cannot make mismatched endpoints seamless. Protected/DRM media, audio-only files, unsupported codecs and indefinite-duration sources are rejected. Still images are static, including the first frame of an animated image format. No procedural live-effect renderer is included beyond the bundled pre-rendered loops.
- Quality/fps caps may require one-time local export, which uses extra energy and cache disk space. Long videos can take time to optimize; active cache files can exceed the 1 GB eviction target. Optimized copies may be SDR and do not promise original HDR or color fidelity. Sources already within the selected bounds play directly. Original quality is available in Performance mode within the fps cap.
- References to imported sources require the source drive to remain available. Bookmarks can follow some moves but not deletion, offline drives, every third-party cloud placeholder state, or all filesystem replacements. Locate File repairs the reference.
- The library supports named collections, assignment, rename, favorites and removal; collection deletion/reordering is not provided. There is no online wallpaper catalog, downloader, audio playback, telemetry, cloud sync or automatic timed playlist.
